# Q-P2-008 (from coding planner P2, round 5) → R-SAMPLE

**Concerns:** D-101 (open), requested action "S0 pools of a fixed size, independent of K, e.g. max(10 × 2K, 128)";
EXP-5 §5 S0, §11 K1; E-SAMPLE-022, -023; `round5/DECISION.md` (adaptive allocation dropped on the −0.0042 Å headroom,
which V5 ruled a capped *lower* bound).

**Question.**
1. Pool size. On the QM9 test csv max K = 30 (computed from
   `round5/ledger/chem_data/qm9_test_smiles_from_local_structure_test.csv`, 940 rows with K, Σ2K = 15,108), so a fixed
   N = 128 per molecule already exceeds 4K for every molecule (8.0 × Σ2K), whereas max(10 × 2K, 128) is still
   K-dependent above K = 6 (13.1 × Σ2K). I propose N_i = max(128, 12 K_i): the first 128 columns form the strictly
   K-free pool for any allocation/headroom analysis, and the columns beyond 128 exist only so that the three Track-P
   replicates at c = 2 use disjoint blocks of 4K (10.1 × Σ2K in total). Is this acceptable as the D-101 fix?
2. Because the allocation drop was decided on a lower bound, should the uncapped oracle − static headroom be
   recomputed on the 128-column pool in Stage A (CPU only, labelled ORACLE, no decision attached unless the user
   reopens Track D)?

**Decision at stake:** Exp 5 pool generation (≈ 2.4 GPU-h) and whether the D-101 record is closed with an uncapped
number.

**Default used (PENDING Q-P2-008):** (1) N_i = max(128, 12 K_i), with the 128-column rule asserted in code; (2) yes,
CPU re-analysis, ORACLE, reported with the cap-binding share.

## Answer (SAMPLE)
Date 2026-10-16. Spec revised: EXP-5 §12.1.

1. **Not max(128, 12K). Use max(128, 4K) for sampling seed 0, and 4K for seeds 1 and 2** (independent seeds rather
   than disjoint blocks of one pool).
   - "Max K = 30" holds for the capped local-structure csv, not for the test csv. `test_smiles.csv` has K from 1 to
     727, 86 molecules with K > 30, and Σ2K = 27,462 [E-SAMPLE-054]. The local-structure csv drops molecules and caps
     K, so it is not the generation universe.
   - With max(128, 4K) the first 128 columns are strictly K-free for every molecule, and Track P needs only 4K.
   - Totals: 151,088 conformers for seed 0 (≈ 1.4 GPU-h) and 54,924 per extra seed. max(128, 12K) would be 232,804
     [E-SAMPLE-054].
2. **Yes. Recompute the uncapped headroom on the 128 block.** CPU, ORACLE, cap-binding share printed, no decision
   unless the user reopens Track D (EXP-5 §11 K1, revised; E-SAMPLE-023 revision note).
