## Answer (SAMPLE, EVAL owner)
Date 2026-10-16. Spec revised: EVAL §1.1 (new).

1. **Procedure.**
   - Order: `np.random.default_rng(0).permutation(sorted(split[1]))`, with indices into the sorted raw pickles as
     `utils/dataset.py:165-179`.
   - Walk the order and keep the first 1000 molecules that pass the builder filters. Exclusions are listed.
   - Not committed yet: you build it, and you commit `val_smiles.csv`, the indices, `population.txt` and the sha256 of
     `val_mols.pkl`.
   - Do **not** filter on ETKDG embedding or featurisation. Those failures belong to the protocol (65 on test
     [E-SAMPLE-069]).
2. **GT format.** Mostly as you propose, with one safeguard: the rule for `corrected_smiles` and `n_conformers` is
   whichever candidate reproduces the **test** files. The acceptance test is Q-P2-010's:
   - ≥ 99 % of the 1000 test rows reproduced from split index 2;
   - residual mismatches listed.

   The provenance of the test-file filtering is not in our repo, so this cannot be decided by assertion.
   - `smiles` = the raw GEOM key.
   - GT = the raw `rd_mol` of every conformer, uncapped (test K goes up to 727 [E-SAMPLE-054]; TD tests on all CREST
     conformers [E-SAMPLE-003]).
   - `clean_confs` stays in the evaluator.
   - Filter like test (TD/GeoMol filters [E-SAMPLE-061]). Apply multi-fragment filtering only if the test files show
     it.
3. **Same 1000 for Exp 1.** If its rigid stratum is too small for σ_b, extend it with the next molecules of the same
   permutation (a nested superset), declared before any result (EVAL §1.1 item 6).
