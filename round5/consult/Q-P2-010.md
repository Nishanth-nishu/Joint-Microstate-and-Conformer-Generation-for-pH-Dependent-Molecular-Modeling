# Q-P2-010 (from coding planner P2, round 5) → R-SAMPLE

**Concerns:** EVAL §1 row "QM9 validation subset: 1000 molecules drawn from split index 1 with a fixed seed; list
committed", EVAL §0 rule 3; EXP-5 §4.3. Used by Exp 1 Gate 0 (validation strata) and the Exp 5 selector choice.

**Question.** Evaluation on validation needs files in the test format: `val_smiles.csv` with `smiles, n_conformers,
corrected_smiles` and `val_mols.pkl` of GT conformers, so that the unmodified `evaluate_confs.py` (including
`clean_confs`, `:47-54`) applies. The test files came with the TD/GeoMol release. How should `corrected_smiles` and
`n_conformers` be defined for validation molecules (e.g. canonical SMILES of the first GT conformer, and the GEOM
conformer count capped at 30 as on the test csv)? Is the cap at 30 part of the protocol?

**Decision at stake:** whether validation numbers are comparable with test numbers (K and the GT cleaning set the 2K
budget and the universe).

**Default used (PENDING Q-P2-010):** the builder is accepted only if, applied to the **test** split, it reproduces
`test_smiles.csv` / `test_mols.pkl` (row count, n_conformers, corrected_smiles) for ≥ 99 % of rows; the rule that
achieves this is used for validation, and the residual mismatches are listed.

## Answer (SAMPLE, EVAL owner)
Date 2026-10-16. Spec revised: EVAL §1.1.

- **Your acceptance test is adopted as the rule.** Applied to split index 2, the builder must reproduce
  `test_smiles.csv` (`smiles`, `n_conformers`, `corrected_smiles`) and the conformer counts of `test_mols.pkl` for
  ≥ 99 % of rows. The candidate rule that passes is then used for validation, and residual mismatches are listed.
- **The cap at 30 is not part of the test protocol.** The test csv has K up to 727 (86 molecules > 30)
  [E-SAMPLE-054]. TD caps K_G at 30 only in training and sets K from all CREST conformers at test [E-SAMPLE-003]:
  "set K to be twice the number of conformers returned by CREST" (PDF p. 17).
- **Validation stays uncapped,** which makes validation numbers comparable with test.
- Embedding and featurisation failures are not filtered. They are part of the protocol.
