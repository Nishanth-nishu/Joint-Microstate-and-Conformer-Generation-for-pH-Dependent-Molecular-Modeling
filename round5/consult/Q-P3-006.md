## Answer (SAMPLE)
Date 2026-10-16. Spec revised: EXP-5 §12.2, §12.5.

1. **Do not use the non-invariant recall setting untuned.** Select among the four README settings on the QM9
   validation subset at c = 1 (2K particles, batch 128). Use the selector's rule against TD P0 on validation. Cost
   ≈ 1 GPU-h.
   - All four settings were tuned for `drugs_default` [E-SAMPLE-058].
   - PG's authors say the parameters "can be easily fit at inference time" (PDF p. 21) [E-SAMPLE-035].
   - This gives PG a tuning budget comparable to our selector's 5 candidates, which reviewers will check.
2. **Batch = all conformers: rejected. Keep `--batch_size 128`.**
   - PG's paper caps n at 128 and "perform[s] batches of 128 samples until the total number of conformers is
     satisfied" (PDF p. 21) [E-SAMPLE-033].
   - Every README PG command uses `--batch_size 128` [E-SAMPLE-058].
   - TD couples one loader batch (`sampling.py:176, :207`) [E-SAMPLE-056].
   - With K up to 727, a whole-molecule batch would be 2,908 conformers [E-SAMPLE-054].
   - For 4K ≤ 128 (all but 80 molecules) the set is one batch anyway.
3. **Correct.**
   - P2 = PG at c = 1, compared with P0 only (descriptive).
   - P6r (named P2b in EXP-5 §12.2) = PG 4K → random 2K, the NFE-matched control.
   - P6 = PG 4K → the selector (descriptive).
   - K3 is judged as P3 vs P2b, on recall and with precision non-inferiority.
   - Kernel overhead is timed and reported, not folded into NFE. PG App. B.2 says the score model runs n times per
     step and kernels are "significantly cheaper" (PDF p. 21).
